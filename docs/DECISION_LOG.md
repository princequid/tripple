## Technical facts recorded (inform decisions; verified from vendor docs)

| ID | Fact | Source | Impact |
|---|---|---|---|
| F-01 | Turso foreign-key enforcement is **off by default** (`PRAGMA foreign_keys`). Whether the setting persists per connection or per HTTP request in Turso's remote mode is **unverified**. In SQLite the pragma is a no-op inside a transaction, and a `batch()` is a transaction. | https://docs.turso.tech/sql-reference/pragmas | SPIKE-02 must prove enforcement. Until then, plan application-level reference checks plus a nightly orphan-check job |
| F-02 | Turso documents both FTS5 as a built-in extension and a newer Tantivy-based `CREATE INDEX … USING fts` that replaces FTS5 on the new engine. | https://docs.turso.tech/features/sqlite-extensions · https://docs.turso.tech/sql-reference/functions/fts | The search syntax depends on the engine version. SPIKE-01 is required |
| F-03 | Drizzle `db.batch()` on libSQL runs its statements in one implicit transaction. | https://orm.drizzle.team/docs/batch-api | Batches are the preferred atomic write pattern (e.g. like + counter) |
| F-04 | Better Auth ships a Drizzle adapter that supports SQLite. | https://better-auth.com/docs/adapters/drizzle | Compatible with Turso through Drizzle. To be confirmed by SPIKE-03 |
| F-05 | `@libsql/client` `batch()` is all-or-nothing. Interactive transactions take a write lock with a 5-second timeout and carry a performance warning. | Turso TS SDK reference (cited in [TECHNOLOGY_EVALUATION.md](00-project-assessment/TECHNOLOGY_EVALUATION.md)) | Batches are the default write pattern; interactive transactions are an exception that needs justification |
| F-06 | Embedded replicas need a persistent filesystem, so they can't be used on serverless hosts. On Vercel every query is a network round trip. | Turso docs (cited in TECHNOLOGY_EVALUATION) | Co-locate DB and app regions; ban N+1 queries; batch reads |
| F-07 | Better Auth's email-OTP plugin stores codes in plain text by default, and its default rate-limit store is in-memory. | Better Auth docs (cited in TECHNOLOGY_EVALUATION) | Configure hashed OTP storage and a database-backed rate limit (D-04, D-12) |
| F-08 | R2 supports presigned PUT but not presigned POST forms; presigned URLs work only on the S3 API endpoint. | Cloudflare R2 docs (cited in TECHNOLOGY_EVALUATION) | No signed size limit, so the server validates size and type after upload (D-16) |
| F-09 | Current stable versions observed on npm (2026-11-12): Next 16.4.6, Drizzle ORM 0.45.4 (1.0 is a release candidate), Better Auth 1.7.22, Tailwind 4.3.5, Zod 4.6.7, sharp 0.35.5; Auth.js v5 is still beta. | npm registry (via TECHNOLOGY_EVALUATION) | Pin exact versions at P08; re-check them then |
| F-10 | The palette's border (`#DDE1E9`, 1.12:1) and neumorphic shadow (`#C5CFDC`, 1.34:1) against the background fail WCAG 1.4.11 (3:1 for component boundaries). | Computed contrast ratios | Inputs, selected states and focus need a ≥3:1 cue (icon, label, accent outline). Folded into D-05 |

| F-11 | **Spike-verified (local):** Turso's new-engine `USING fts` index is **experimental** (needs `--experimental-index-method`), and FTS5 does not exist on the new engine. FTS5 works on libSQL (p95 31 ms / 10k rows). | [ADR-001](02-architecture/ARCHITECTURE_DECISIONS.md) | D-07 resolved to FTS5 on libSQL |
| F-12 | **Spike-verified:** `drizzle-kit push` offers to drop FTS tables and, when filtered, rebuilds tables and **silently drops their triggers**. | ADR-001 | `push` forbidden on persistent DBs; FTS in custom migrations; CI trigger test |
| F-13 | **Spike-verified (local):** `@libsql/client` local mode has `foreign_keys` ON by default, and `batch()` is fully atomic (an earlier statement rolls back if a later one fails). Remote mode unverified. | [ADR-002](02-architecture/ARCHITECTURE_DECISIONS.md) | Client factory enables and asserts FKs; T-06b pending |
| F-14 | **Spike-verified:** Better Auth 1.7.14 email OTP on Drizzle/libSQL works end to end in Next 16 (hashed OTP, 5-attempt lockout, origin check, DB rate limiter at 3/min on OTP routes). Without a trusted client-IP header, all users share one rate-limit key. | [ADR-003](02-architecture/ARCHITECTURE_DECISIONS.md) | Configure IP header for the host in P09-03 |
| F-15 | **Spike-verified:** sharp processes a 55 MB 4800×3600 image into 4 WebP derivatives + palette in ~2 s at ~316 MB peak RSS (single thread). | [ADR-004](02-architecture/ARCHITECTURE_DECISIONS.md) | In-request processing viable (D-15); function ≥ 1 GB / ≥ 30 s |
