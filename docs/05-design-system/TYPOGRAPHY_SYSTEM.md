Typography carries the minimalism pillar: hierarchy comes from size, weight and space, not from colour or decoration.

---

## 1. Typeface and licence

| Item | Value |
|---|---|
| Family | Inter (variable, `wght` axis 100–900; we use 400–600) |
| Licence | SIL Open Font License 1.1 — free to self-host and bundle; the licence text ships with the font files. No reference-product font (Mona Sans, WF Visual Sans) is used (A-10) |
| Delivery | `next/font/google`, which downloads the font **at build time** and serves it from the app's own origin (no runtime request to Google, no third-party cookie) |
| Subsets | `latin` for R1; add `latin-ext` when non-English seed or user content appears (adds Central/Eastern European glyphs) |
| Display | `swap` (text renders immediately in the fallback, then swaps) |
| Fallback metrics | `adjustFontFallback` (default `true`) generates a size-adjusted local fallback so the swap causes no layout shift (CLS) |
| Exposed as | CSS variable `--font-inter`, consumed by the `--font-sans` token |

### 1.1 Loading specification (for P10-01; not a project file yet)

```ts
// src/app/fonts.ts  (specification)
import { Inter } from 'next/font/google';

export const inter = Inter({
  subsets: ['latin'],
  display: 'swap',
  variable: '--font-inter',
  // variable font: no `weight` list needed; we only use 400/500/600
});
// layout.tsx: <html lang="en" className={inter.variable}>
```

### 1.2 Fallback stack

```css
--font-sans: var(--font-inter), ui-sans-serif, system-ui, -apple-system, "Segoe UI",
             Roboto, "Helvetica Neue", Arial, "Noto Sans", sans-serif,
             "Apple Color Emoji", "Segoe UI Emoji";
--font-mono: ui-monospace, "SFMono-Regular", Menlo, Consolas, "Liberation Mono", monospace;
```

Monospace is used only for hex values and codes shown to users (e.g. a colour value in shot details, R3).

### 1.3 OpenType features

| Feature | Where | Why |
|---|---|---|
| `font-variant-numeric: tabular-nums` | Counts (likes, views), stats, OTP cells, timestamps in lists | Numbers don't jitter when they change (optimistic like counts) |
| `font-feature-settings: "cv11"` (single-storey a) | Not used | Keep Inter's default forms for legibility |
| Optical sizing | Automatic | Inter variable handles it |

## 2. Weights

| Weight | Token | Use |
|---|---|---|
| 400 Regular | `font-weight-regular` | Body, captions, descriptions, inactive pills |
| 500 Medium | `font-weight-medium` | Labels, metadata emphasis, nav links, author names in cards |
| 600 Semibold | `font-weight-semibold` | Headings, button labels, selected pill/tab labels, display |
| 700 Bold | — | **Not used.** 600 gives enough contrast at every size in the scale; 700 adds a fourth weight for no hierarchy gain. Reconsider only if the D-01 wordmark needs it |

Because 700 is not used, "large text" in WCAG terms means **≥ 24 px** in this system (the 18.66 px bold threshold never applies).

## 3. Type scale

Fluid sizes interpolate linearly between 360 px and 1440 px viewports and are fixed outside that range. The `rem + vw` form keeps text zoomable (WCAG 1.4.4). Clamp values were generated by the T-15 script (§ "Fluid type" in the [report](../08-testing/design/T-15_CONTRAST_REPORT.md)).

| Role | Size 360 → 1440 | CSS value | Line height | Weight | Letter-spacing | Use |
|---|---|---|---|---|---|---|
| display | 40 → 64 px | `clamp(2.5rem, 2rem + 2.2222vw, 4rem)` | 1.1 | 600 | −0.025em | Landing hero (one per page, max) |
| h1 | 32 → 48 px | `clamp(2rem, 1.6667rem + 1.4815vw, 3rem)` | 1.15 | 600 | −0.02em | Page title: profile name, search results title |
| h2 | 26 → 36 px | `clamp(1.625rem, 1.4167rem + 0.9259vw, 2.25rem)` | 1.2 | 600 | −0.015em | Section titles, auth heading |
| h3 | 21 → 26 px | `clamp(1.3125rem, 1.2083rem + 0.4630vw, 1.625rem)` | 1.3 | 600 | −0.01em | Shot detail title, modal titles, "More by …" |
| h4 | 18 → 20 px | `clamp(1.125rem, 1.0833rem + 0.1852vw, 1.25rem)` | 1.35 | 600 | −0.005em | Sub-sections, empty-state titles, about-panel headings |
| body-lg | 17 → 18 px | `clamp(1.0625rem, 1.0417rem + 0.0926vw, 1.125rem)` | 1.6 | 400 | 0 | Shot description, profile bio, intros |
| body | 16 px | `1rem` | 1.6 (25.6 px) | 400 | 0 | Default text, inputs |
| body-sm | 14 px | `0.875rem` | 1.55 | 400 | 0 | Dense secondary text on desktop (never the main body on mobile) |
| label | 14 px | `0.875rem` | 1.25 (≈ 18 px) | 500 (600 in buttons, selected) | 0.005em | Buttons, pills, tabs, form labels, nav links |
| caption | 13 px | `0.8125rem` | 1.45 | 400 | 0.005em | Helper text, field errors, timestamps, disclaimers |
| metadata | 12 px | `0.75rem` | 1.4 | 500 | 0.02em | Counts on cards, badges (tabular nums) |

**Shot detail title** uses h3 (not h1 size) visually while being the page's `<h1>` element: the media is the hero, so its title stays modest. Visual role and semantic level are independent; every page still has exactly one `<h1>`.

## 4. Rules

1. **Mobile body ≥ 16 px.** Body and every text input are 16 px at 360 px (also prevents iOS zoom on focus). `body-sm` is never the running text on mobile.
2. **Minimum size 12 px** (`metadata`), used only for short labels and counts; never for sentences.
3. **Measure:** running text max 68ch (`max-inline-size: 68ch`); shot descriptions and bios 60–72ch.
4. **Line height** stays unitless so user text-spacing overrides work (WCAG 1.4.12). No fixed heights on text containers.
5. **Headings** use `text-wrap: balance`; paragraphs use `text-wrap: pretty` (progressive enhancement).
6. **Truncation:** card titles one line with ellipsis and the full title in the link's accessible name; author names one line; descriptions never truncated without a "Show more" control.
7. **Case:** sentence case everywhere. No all-caps labels (the reference product's letter-spaced uppercase toggle is not reused). Badges use one or two short sentence-case words.
8. **Colour:** headings and body in `text-primary`; secondary lines in `text-secondary`; `#9273C7` lavender only for emphasis words at display/h1/h2 sizes (≥ 26 px, passes 3:1).
9. **Numbers:** counts abbreviated (`1.2k`, `3.4m`) with the exact number in `title`/accessible text; tabular nums.
10. **Language:** `<html lang>` set; user-generated text gets `dir="auto"`.

## 5. Hierarchy examples

| Screen | Element → role |
|---|---|
| Feed (explore) | Page heading (visually hidden or h2 "Popular shots") · card title `label` 500 on hover bar · author `label` 500 · counts `metadata` |
| Shot detail | Title `h3` (as `<h1>`) · author `label` 600 + "Follow" link · description `body-lg` · "More by …" `h4` |
| Profile | Name `h1` · headline `body-lg` `text-secondary` · stats `label` + `metadata` · tabs `label` |
| Auth | Heading `h2` · supporting line `body` `text-secondary` · field label `label` · helper/error `caption` · disclaimer `caption` |
| Modal | Title `h3` · body `body` · actions `label` 600 |
